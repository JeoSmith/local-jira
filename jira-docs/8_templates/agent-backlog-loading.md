# 백로그 적재 지침 (에이전트용 템플릿)

> **쓰는 법.** 아래 「지침 본문」을 프로젝트의 `CLAUDE.md`(또는 에이전트가 읽는 규약 파일)에
> 그대로 붙여 넣고, `LJ`·경로·포트만 그 프로젝트 값으로 바꾼다.
>
> **왜 제품 기능이 아니라 문서인가.** PRD **D16**이 AI 정제(R22)를 철회했다. 제품은 LLM을
> 호출하지 않는다. 적재를 하는 주체는 이미 프로젝트에 들어와 있는 에이전트이고, 그 에이전트는
> 코드베이스·요구사항 문서·기존 스토리를 다 읽는다 — 텍스트 한 덩어리만 보는 정제 API보다
> 나은 입력을 이미 갖고 있다. 그래서 필요한 것은 기능이 아니라 **언제 무엇을 하라는 약속**이다.

---

## 지침 본문 (여기부터 복사)

### 작업 시작 전 백로그를 적재한다

이 프로젝트의 할 일은 Local Jira 보드에 있다. **코드를 건드리기 전에 보드를 먼저 맞춘다.**

#### 1. 보드를 읽는다

```
localjira issue list --project LJ --json
```

이미 있는 이슈를 **다시 만들지 않는다.** 같은 일을 두 번 적재하면 사람이 중복을 지우는 데
시간을 쓰고, 그건 적재가 아낀 시간보다 크다.

#### 2. 없는 것만 만든다

요구사항 문서·이슈 트래커·대화에서 나온 할 일 중 보드에 없는 것을 이슈로 만든다.

```
POST http://127.0.0.1:8080/issues
Authorization: Bearer $LOCALJIRA_TOKEN
Idempotency-Key: <실행마다 고유한 값>
Content-Type: application/json

{"project":"LJ","type":"story","title":"...","description":"...",
 "labels":["M1","P1"],"acceptance":[{"text":"Given … When … Then …"}]}
```

**HTTP API를 쓴다. CLI로 만들지 않는다.** `localjira issue create`는 주체를 `human`으로
고정하므로, CLI로 적재하면 AI가 만든 이슈가 **사람이 만든 것으로 기록된다**. 화면의 `agent`
배지가 거짓이 되고 사람이 검토할 근거가 사라진다. (`r13c`가 이 구멍을 막는 스토리다.)

지킬 것:

- **상태를 지정하지 않는다.** 생성 시 상태는 항상 `BACKLOG`다(S1-D1).
- **`Idempotency-Key`를 싣는다.** 재시도가 이슈를 두 개 만들지 않는다(r15).
- **인수조건은 검증 가능하게 쓴다.** "잘 동작한다"는 인수조건이 아니다. 무엇을 실행해 무엇을
  확인하면 참인지 적는다. 지금 마일스톤에서 확인할 수 없는 조건은 넣지 않는다.
- **추측을 이슈로 만들지 않는다.** 근거가 문서·코드·대화에 있는 것만 적재하고, 애매하면
  이슈 대신 질문으로 남긴다.

#### 3. 멈춘다

적재가 끝나면 **거기서 멈추고 사람에게 보고한다.** 적재한 건수와, 판단이 갈렸던 항목을 말한다.

`BACKLOG` 이슈는 claim할 수 없다. 시도하면 `E_CLAIM_NOT_REFINED`로 거부된다 — 이건 버그가
아니라 설계다. **사람이 `TODO`로 올린 것만** 착수한다.

#### 4. 커밋하지 않는다

적재하면 `.localjira/` 아래에 파일이 생기지만 **커밋은 사람이 한다**(D4). 커밋 전이라 사람이
`git -C .localjira diff`로 전부 훑어보고 마음에 안 들면 `git -C .localjira checkout .`으로
통째로 되돌릴 수 있다. 이것이 검토 관문이므로 앞질러 커밋하지 않는다.

### 작업 중

- 착수할 때 `POST /issues/{key}/claim`으로 선점하고, 60초마다 heartbeat를 보낸다.
- 판단이 필요하면 코멘트를 `question`으로 남긴다. 미해결 질문이 있는 이슈는 게이팅에 걸린다.
- 끝나면 `IN_REVIEW`로 올린다. **`DONE`은 사람이 확인하고 옮긴다.**

## 준비물 (사람이 한 번만)

1. **에이전트 계정과 토큰**을 만들고 `issue:edit`을 준다. 기본 에이전트 scope에는 생성 권한이
   없다 — 적재를 시킬 때만 의도해서 부여한다.
   기본 scope: `issue:read` · `issue:comment` · `issue:transition` · `run:write`.
   `issue:rank`·`issue:delete`는 사람 전용이다(D9). **`issue:delete`는 주지 않는다** — 에이전트가
   자기가 만든 것을 스스로 지울 수 있으면 검토 관문이 관문이 아니다.
2. 토큰을 `LOCALJIRA_TOKEN` 환경변수에 둔다. 명령줄 인자로 넘기면 `ps`와 셸 히스토리에 남는다.
3. 서버를 띄운다: `localjira serve --port 8080`

## 이 방식이 기대는 것

적재를 제품 기능 대신 지침으로 두는 게 안전한 근거는 셋이다. 하나라도 무너지면 이 지침은
다시 생각해야 한다.

| 관문 | 무엇을 막나 | 근거 |
|---|---|---|
| `BACKLOG`는 claim 불가 | 에이전트가 자기가 적재한 걸 스스로 착수하는 것 | §6.1, `E_CLAIM_NOT_REFINED` |
| 미커밋 파일이 곧 초안 | 검토 없이 이력에 남는 것 | D4·R25 |
| `created_by_kind=agent` 배지 | AI 산출물이 사람 것처럼 보이는 것 | §8 |

세 번째가 **HTTP API를 쓰라고 못박은 이유**다. CLI로 적재하면 그 관문 하나가 조용히 사라진다.
