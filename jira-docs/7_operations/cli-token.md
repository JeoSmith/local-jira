# 자기 보드에 쓸 토큰 만들기

`r13c` 이후 **보드에 쓰는 명령은 주체를 밝혀야 한다.** 토큰이 없으면 거부되고, 파일도 만들어지지
않는다. 주체를 모르는 쓰기는 주체를 지어내는 것보다 실패하는 편이 낫다는 것이 그 결정(S6-D3)이고,
그 대가가 이 문서다 — 한 번은 토큰을 만들어야 한다.

토큰 없이도 **읽기는 된다**: `issue list`·`issue show`·`index status`·`doctor`. 자격 증명이
고장난 보드를 `doctor`가 진단하지 못하면 안 되기 때문이다.

## 1. 발급

보드 폴더(`.localjira`가 있는 저장소)에서, 자기 계정의 비밀번호로 자기에게 발급한다.

```
localjira token create --user <계정> --password '<비밀번호>' \
  --label '내 노트북 CLI' \
  --expires-in-days 0 \
  --scope issue:read --scope issue:edit --scope issue:transition \
  --scope issue:rank --scope issue:delete
```

- `--expires-in-days 0`은 **무기한**이다. 생략하면 90일이고, 만료되면 같은 명령으로 다시 만든다.
- scope는 필요한 것만 준다. 위 다섯이면 보드 정리에 쓰는 일(수정·상태 전이·순서·삭제)이 모두 든다.
  적재만 시킬 거라면 `issue:read`와 `issue:edit`이면 충분하다.
- **토큰 원문은 이때 한 번만 stdout에 나온다.** 못 받아 적으면 다시 만드는 수밖에 없다.
  안내문은 stderr로 나가므로 `> token.txt`로 받으면 토큰만 깨끗이 담긴다.

로컬 실행을 권한으로 치지 않는 것이 요점이다(S6-D3). 그 가정이 애초에 CLI가 주체를 지어내게
만든 원인이었다.

## 2. 환경변수에 둔다

```
export LOCALJIRA_TOKEN="ljp_..."
```

셸 프로필(`~/.zshrc` 등)에 넣어 두면 매번 칠 일이 없다.

**`--token` 인자로 넘기지 않는다.** 명령줄 인자는 `ps`에 보이고 셸 히스토리에 남는다. 인자도
지원하지만 그건 한 명령만 다른 주체로 실행할 때 쓰는 것이고, 평소 경로는 환경변수다.

## 3. 같은 토큰이 API에도 통한다

```
curl -H "authorization: Bearer $LOCALJIRA_TOKEN" http://127.0.0.1:4000/issues
```

CLI와 HTTP가 같은 저장소를 읽고 role→kind 매핑도 같으므로, **어느 경로로 쓰든 기록이 같다.**
그 사실 자체를 테스트로 걸어 두었다(`test/auth/cli-token.test.ts`).

## 주체는 계정의 역할을 따른다

| 계정 역할 | 파일에 남는 값 | 화면 |
|---|---|---|
| `admin`·`member` | `created_by_kind: human` | 배지 없음 |
| `agent` | `created_by_kind: agent` | **"AI 유래"** 표시 (S6-D5) |

에이전트에게 적재를 시킬 거라면 `--role agent` 계정으로 **따로** 발급해야 한다. 사람 계정 토큰을
에이전트에게 주면 AI 산출물이 사람이 만든 것으로 기록되고, D16이 기댄 관문 하나가 사라진다.
적재 절차는 [백로그 적재 지침](../8_templates/agent-backlog-loading.md)에 있다.

## 폐기

**토큰으로는 토큰을 폐기할 수 없다.** §6.4의 일곱 scope 중 `token:manage`를 덮는 것이 없다 —
토큰은 보드를 *쓰는* 것이지 *운영하는* 것이 아니다. 폐기는 비밀번호로 로그인한 세션에서 한다:

- 웹 **설정 → 액세스 토큰 → [폐기]**
- 또는 `DELETE /tokens/{token_id}`를 세션 쿠키로

폐기는 **다음 요청부터** 즉시 적용된다(`E_TOKEN_REVOKED`). 검사가 매번 그 행을 읽으므로 무효화할
캐시가 없다(r13a).

## 토큰은 보드에 남지 않는다

해시만 `.local/credentials.sqlite`에 있고, 그 디렉터리는 `.gitignore` 대상이라 커밋·푸시되지
않는다(N6, D5). 원문은 이슈 파일·이벤트·오류 메시지 어디에도 실리지 않는다 — 오류 스트림도
로그이기 때문이다.

기기를 옮기면 토큰은 따라가지 않는다. `.local/`은 백업 대상이 아니고 **기기별 재발급이 정상
경로**다(D5).

## 잃어버렸을 때

원문을 다시 볼 방법은 없다. 새로 발급하고, 쓰던 것은 위 절차로 폐기한다. 설정 화면의
`마지막 사용` 시각으로 아직 쓰이는 토큰인지 판단할 수 있다.
