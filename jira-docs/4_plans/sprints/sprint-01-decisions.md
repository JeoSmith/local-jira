# Sprint 01 착수 결정 로그

Sprint 01 착수 조건 — *"각 스토리의 `⚠ 미정` 중 API·파일 스키마·복구 테스트를 바꾸는 항목은
구현 착수 전에 결정한다"* — 의 이행 기록이다.

M1 스토리 20건에 남아 있던 `⚠ 미정` **24건**을 세 갈래로 나눴다.

## 2. 이번에 확정 (S1-D1 ~ S1-D13)

### 이슈 생성·수정

**S1-D1 — 생성 시 상태는 항상 `BACKLOG`. `points`는 0~100 정수 또는 `null`.** *(r01a)*
클라이언트가 `status`를 실어 보내면 **400**이다. 상태 변경 경로를 전이 API 하나로 묶어야
게이팅(claim·미해결 코멘트·`blocked_by`)과 이벤트 `verb`가 한 곳에서만 결정된다. 생성으로
`DONE` 이슈를 만들 수 있으면 그 검증이 두 곳으로 갈라진다.
`points`는 피보나치를 강제하지 않는다 — 추정 척도는 팀 규약이지 시스템 제약이 아니다.
`null`은 무추정이며 번다운 분모에서 빠진다(D8).

**S1-D2 — 상태 전이는 전용 엔드포인트 `POST /issues/{key}/transitions`.** *(r01b)*
`PUT`/`PATCH` 본문에 `status`가 오면 **400**이다. 전이는 일반 필드 수정과 검증 규칙·감사
의미가 다르고, 에이전트에게는 claim 보유가 추가로 요구된다(§6.1). 한 요청에 섞이면
"제목도 바꾸고 DONE으로 옮기는" 요청의 실패 단위가 모호해진다.
`If-Match`는 두 엔드포인트 모두 필수다(D15).

**S1-D3 — `strategy=promote` 대상에 `subtask`가 있으면 400으로 거부한다.** *(r02a)*
승격 결과가 "부모 없는 subtask"가 되어 §5.1 계층 규칙을 깨기 때문이다. 응답에 문제되는
subtask 키를 나열하고, 사용자는 부모를 다시 지정하거나 `cascade_cancel`을 고른다.
계층 규칙을 조용히 예외 처리하는 쪽은 택하지 않는다 — 한 번 허용하면 이후 모든 계층
검증이 "단, 승격된 subtask는 제외"를 달고 다녀야 한다.

### 관계 링크

**S1-D4 — 링크는 선언한 쪽 파일에만 저장하고, 역방향은 인덱스가 계산한다.** *(r02b)*
양방향 저장은 링크 하나에 **두 파일**을 고쳐야 해서 머지 충돌 면적이 두 배가 되고, 한쪽만
반영된 부분 실패 상태가 생긴다. `A blocks B`를 선언하면 `A` 파일에만 기록되고, `B`의
`blocked_by`는 `issue_links` 역참조 인덱스로 조회한다.
- 자기 자신을 가리키는 링크는 **400**
- 같은 `(from, to, kind)` 중복 요청은 **멱등 200**(no-op)
- `A blocks B`와 `B blocked_by A`가 양쪽에서 각각 선언되면 인덱스가 같은 관계로 합친다

**S1-D5 — `CANCELLED` 차단자는 해제된 것으로 본다.** *(r02b)*
취소된 작업을 기다리며 영원히 `claimable=false`로 남는 것을 막는다. 다만 API가 돌려주는
차단 사유에는 `blocked_by_cancelled`를 구분해 실어, 사람이 "정말 끝나서 풀린 것"과
"취소돼서 풀린 것"을 구별할 수 있게 한다.

### 조회 API

**S1-D6 — 같은 파라미터 반복은 OR, 다른 파라미터는 AND.** *(r04a)*
`?label=web&label=perf&status=TODO` → `(web OR perf) AND TODO`.
Jira·GitHub과 같은 관행이고, 클라이언트가 OR 결과에서 교집합을 만드는 것은 쉬운 반면
AND 결과로 합집합을 만드는 것은 불가능하다.

**S1-D7 — 커서 페이지네이션. `?limit=50&cursor=<opaque>`, 기본 50 · 최대 200.** *(r04a)*
정렬 키가 `(rank, uid)`로 결정적이라 커서가 성립한다. offset은 앞쪽에 삽입이 일어나면
항목을 건너뛰거나 중복시키는데, 에이전트가 목록을 훑으며 작업을 집는 이 제품에서는
건너뛴 이슈가 곧 누락된 작업이 된다. 응답에 `next_cursor`를 싣고, 커서는 불투명 문자열로
다룬다.

**S1-D8 — 예약어는 `sprint=active`와 `sprint=none` 둘만 지원한다.** *(r04a)*
§4 S3의 에이전트 시나리오가 `sprint=active`를 전제한다. 예약어를 더 늘리지 않는 이유는
파라미터 문법이 곧 쿼리 언어로 자라기 때문이다.

**S1-D9 — M1 전문 검색 대상은 제목 · 본문 · 표시 키(현재 + `former_keys`).** *(r04b)*
코멘트는 M4에서 코멘트 자체가 생긴 뒤 색인에 추가한다. 담당자·라벨은 구조화 필터로 이미
정확히 걸러지므로 전문 검색에 넣으면 노이즈만 는다.

### 인증·권한

**S1-D10 — 사람 세션은 HTTP-only · SameSite=Strict 쿠키, 12시간 슬라이딩 만료.** *(r12a)*
로컬 웹앱이라 토큰을 JS가 읽을 수 있게 둘 이유가 없다. 에이전트는 PAT를 헤더로 쓰므로
쿠키 정책과 무관하다.

**S1-D11 — `member`는 타인이 만든 이슈도 삭제할 수 있다.** *(r12b)*
삭제 주체가 이벤트에 남고 파일이 git에 있어 되돌릴 수 있다. 소규모 팀 도구에서 삭제를
`admin`으로 묶으면 1인 사용 시 매번 막힌다. 세분화된 RBAC는 §3 비목표다.
에이전트는 별개다 — `issue:delete`는 기본 scope에서 제외된다(D9).

**S1-D12 — 자기 계정의 비밀번호·표시명 변경은 역할과 무관하게 허용한다. 역할 변경은 `admin`만.** *(r12b)*

### 정렬

**S1-D13 — LexoRank 파라미터를 고정한다.** *(r03)*

| 항목 | 값 |
|---|---|
| alphabet | base-36 `0123456789abcdefghijklmnopqrstuvwxyz` |
| 초기 간격 | 첫 항목 `hzzzzz`, 인접 항목 사이 최소 간격 8 |
| 길이 상한 | 32자 |
| 재균형 트리거 | 새 rank를 만들 수 없거나 길이가 상한을 넘을 때 |
| 재균형 폭 | 해당 위치 앞뒤 각 64개(최대 128개) 구간을 균등 재배치 |

대소문자를 섞지 않는 이유는 정렬이 로케일·파일시스템에 따라 달라지는 것을 피하기 위해서다.
ADR-005가 못박은 대로 **이 값들을 바꾸는 것은 저장 형식 변경**이므로 `schema_version`과
마이그레이션이 필요하다. 구현 시 property test로 고정한다(§4 참조).
