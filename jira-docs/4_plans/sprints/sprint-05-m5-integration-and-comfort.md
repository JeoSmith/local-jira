## 1. 목표

**커밋 메시지에만 남아 끊기던 흔적을 이슈에 붙이고, 손이 마우스를 덜 타게 한다.**

M3·M4로 에이전트가 이슈를 집고 결과를 보고하고 사람의 질문에 막히게 됐다. 남은 구멍은
PRD §2가 P2로 지목한 것이다 — "이 이슈를 누가 어디까지 했나"가 커밋 메시지에만 남아 끊긴다.
이 스프린트가 끝나면:

1. `Issue: LJ-12` 트레일러만 달면 그 커밋이 이슈에 붙는다. 옛 표시 키로 쓴 트레일러도 산다.
2. 키보드만으로 이슈를 찾아가고 자주 쓰는 명령을 실행한다.
3. 지금 보고 있는 백로그를 CSV·JSON으로 내려받는다.

## 2. AI 정제 두 건은 이 스프린트에 넣지 않는다

**PRD가 그렇게 적어 뒀다.** §12는 M5를 "AI 정제(**Q10 선결**)·커밋 연결·편의"로 쓰고, 문서
머리말은 "남은 열린 질문은 Q10(LLM 전송 정책) 하나이며 M5에만 걸린다"고 못박는다. Q10은
아직 답이 없다.

내가 새로 만든 유보가 아니라 문서에 이미 있는 선결 조건이다. 그리고 이 결정은 코드로 대신할
수 있는 종류가 아니다 — r22a는 이 프로젝트에서 **유일하게 네트워크가 필요한 기능**이고(N4가
"LLM 기능을 제외한 전 기능"이라고 쓴 그 예외), 사용자의 API 키와 호출당 비용이 걸린다.

그래서 r22a·r22b(13점)는 이 스프린트의 범위에 넣지 않는다. 이월(carry-over)로 적지도 않는다 —
이월은 착수했다가 못 끝낸 것을 뜻하고, 이 둘은 **착수 조건이 아직 없다.** Q10이 닫히면
Sprint 06으로 계획한다.

## 3. 이번 스프린트의 성격 — 앞의 넷과 다른 점

Sprint 01은 저장 코어, 02는 화면, 03은 권한과 동시성, 04는 시간이었다. **이번은 경계다 —
이 도구가 소유하지 않은 데이터를 읽어 온다.**

**첫째, 코드 저장소를 읽는다.** 지금까지 git은 `.localjira/` 데이터 worktree만 다뤘다(D1).
커밋 트레일러 스캔은 반대쪽, 사람이 코드를 커밋하는 브랜치를 읽는다. 읽기 전용이고(D4),
읽어 온 정보는 **인증된 주체로 취급하지 않는다** — §5.7이 "커밋 author를 인증된 actor로
간주하지 않는다"고 정해 뒀다.

**둘째, 읽기 전용 기능이 대부분이다.** 내보내기와 팔레트는 도메인 파일을 하나도 바꾸지
않는다. 그래서 이 스프린트의 인수조건 중 여럿이 "바뀌지 않았음"을 확인하는 형태다.

**셋째, 스택 규약이 스토리와 충돌한다.** r24a의 인수조건 하나가 "shadcn/ui + lucide 규약대로
렌더된다"고 쓰여 있는데, **S2-D1이 의존성 0개 바닐라를 유지하기로 이미 닫았다.** 그 인수조건은
"라이트·다크 양쪽에서 기존 화면과 같은 규약으로 렌더된다"로 읽는다 — 되돌리려면 ADR이 필요한
결정이고, 팔레트 하나 때문에 뒤집을 이유가 없다.

## 4. 웨이브와 게이트

### Wave 1 — 커밋 연결 (8점)

`r23` 커밋 트레일러 스캔

**Gate 1** — 코드 브랜치에 `Issue: LJ-12` 트레일러를 단 커밋이 이슈 상세에 보인다. 재키잉으로
`former_keys`에 들어간 옛 키로 쓴 트레일러도 현재 키 이슈에 붙는다. 스캔을 두 번 돌려도 연결이
중복되지 않는다. 코드 저장소에 커밋·태그·체크아웃이 하나도 생기지 않는다.

### Wave 2 — 편의 (8점)

`r24a` 키보드 단축키·커맨드 팔레트 · `r24b` CSV/JSON 내보내기

**Gate 2** — 팔레트가 키보드만으로 열리고 닫히고, 포커스가 밖으로 새지 않는다. 텍스트 입력에
포커스가 있을 때 단일 문자 단축키가 발동하지 않는다. 현재 필터가 걸린 결과가 그대로
내려받아지고, 내보내기 후 미커밋 배지 건수가 그대로다.

## 6. 결정

### S5-D1 — 커밋 연결은 인덱스에만 두고, 파일 SoT는 커밋이 대신한다 *(2026-07-30, r23)*

스토리가 물은 것: 연결 정보를 이슈 frontmatter에 남길지, 인덱스에만 둘지.

**인덱스에만 둔다.** frontmatter에 쓰면 스캔이 도메인 파일을 고치게 되고, 그러면 스캔을 돌릴
때마다 미커밋 배지가 올라간다 — D4가 "서비스는 커밋하지 않는다"고 했으므로 그 변경은 사람이
커밋해야 하고, 사람은 자기가 하지 않은 변경을 커밋하게 된다.

파일 SoT 원칙이 요구하는 것은 "인덱스를 지워도 복원 가능하다"이고, 여기서는 **그 원본이
git 히스토리 자체**다. 커밋은 이 도구가 지울 수 없고 바꿀 수 없는 기록이며, 재빌드 시 다시
스캔하면 같은 연결이 나온다. 인덱스가 캐시인 것은 이슈 파일에 대해서와 똑같다.

`AgentRun.commits[]`(run이 스스로 보고한 것)와는 별개로 표시한다 — §5.1이 그 필드를 run에만
두었고, 하나는 에이전트의 주장이고 하나는 히스토리의 사실이다.

### S5-D2 — 스캔은 사람이 돌리거나 기동 시 한 번 *(2026-07-30, r23)*

주기 폴링도 git 훅도 두지 않는다. 폴링은 이 도구가 코드 저장소를 상시 들여다보게 만들고, 훅은
사용자의 `.git/hooks`를 이 도구가 고치는 일이다 — D4의 "서비스는 저장소를 건드리지 않는다"와
같은 성질의 선이다.

범위는 **현재 HEAD의 히스토리, 최근 1,000커밋**이다. 상한을 두는 이유는 수만 커밋 저장소에서
매 기동마다 전량을 읽을 수 없고, 트레일러가 달린 커밋은 최근작일 가능성이 압도적이기 때문이다.
상한은 설정으로 올릴 수 있게 한다.

### S5-D3 — 트레일러는 `Issue:`, 대소문자 무관, 한 커밋에 여러 개 허용 *(2026-07-30, r23)*

`Issue:` 한 가지만 인식하고 대소문자는 구분하지 않는다(`issue:`도 같다). 한 커밋에 여러 줄이
있으면 **전부 연결한다** — 한 커밋이 두 이슈를 건드리는 것은 흔하고, 첫 줄만 보는 규칙은 두
번째 줄을 쓴 사람이 왜 안 붙는지 알 수 없게 만든다.

본문 자유 텍스트의 `LJ-12` 언급은 연결하지 않는다(스토리 인수조건). 트레일러는 의도이고 본문
언급은 이야기다.

### S5-D4 — 없는 키를 가리키는 트레일러는 보류하고 다시 시도한다 *(2026-07-30, r23)*

무시하지 않는다. `Issue: LJ-999`가 아직 없는 이슈를 가리키는 경우는 **트레일러를 먼저 쓰고
이슈를 나중에 만든 순서**일 수 있고, 그때 조용히 버리면 다시 붙을 기회가 없다.

미해결 참조로 인덱스에 남기고 다음 스캔에서 다시 해석한다. rebase·amend로 해시가 바뀐 연결은
재스캔 때 히스토리에 없으므로 정리한다 — 고아 연결을 남기면 없는 커밋을 가리키는 링크가 쌓인다.

### S5-D5 — 팔레트는 이동과 검색만, 쓰기는 하지 않는다 *(2026-07-30, r24a)*

허용하면 §5.2 전이표·§6.1 claim 결합·§5.4 `If-Match`를 팔레트 경로에서도 지켜야 하고, 그것은
**두 번째 쓰기 경로**다. 이 프로젝트가 세 번 확인한 대로, 같은 규칙의 사본은 어긋난다.

"신규 이슈" 명령은 생성 폼을 여는 것까지다 — 쓰기는 기존 경로가 한다. 필터 적용과 화면 이동은
읽기이므로 허용한다.

키 바인딩은 `Cmd/Ctrl+K`(팔레트) · `?`(도움말) · `Esc`(닫기) · `↑↓`(이동) · `Enter`(실행)다.
단일 문자 바인딩은 텍스트 입력에 포커스가 없을 때만 듣는다. 사용자별 키맵 커스터마이즈는 범위
밖이다 — 저장할 곳이 `.local/`(기기 고유, 백업 비대상, D5)뿐이라 기기를 옮기면 사라진다.

격리된 이슈는 **결과에 보이되 표시한다.** §5.6이 "일반 조회·집계에서 제외"라고 했지만, 깨진
이슈를 찾아가려는 사람이 쓰는 도구가 팔레트다. 숨기면 고칠 방법이 사라진다.

### S5-D6 — CSV의 중첩 필드는 JSON 문자열, 인코딩은 BOM 있는 UTF-8 *(2026-07-30, r24b)*

`links[]`·`acceptance[]`·`labels[]`·`former_keys[]`는 **JSON 문자열 한 칸**으로 넣는다. 구분자로
이어 붙이면 라벨에 그 구분자가 들어간 순간 되돌릴 수 없고, 컬럼으로 펼치면 항목 수에 따라
헤더가 달라져 같은 조건의 두 내보내기가 다른 모양이 된다.

**UTF-8 BOM을 붙인다.** 스프레드시트로 열려고 내보내는 파일인데, BOM 없는 UTF-8 CSV를 Excel이
깨뜨린다. 구분자는 쉼표를 쓴다.

대상은 **이슈만**이다. R24는 백로그 내보내기로 쓰였고, 스프린트·코멘트·run까지 넣으면 CSV 한
장에 담기지 않는 모양이 된다. 내려받기는 브라우저가 하고 서버는 경로에 쓰지 않는다 —
`.localjira/` 아래에 쓰면 도메인 데이터를 오염시킨다.

격리 항목은 기본 제외 + 옵션 포함이며, 포함할 때는 `quarantined: true`로 표시해 정상 항목과
섞이지 않게 한다. 내보내기는 조회이므로 이벤트를 만들지 않는다(N7).

### 착수 뒤에 드러난 것 — 웹 UI에 이슈 생성 경로가 없다

r24a의 AC10은 "툴바 우측의 [신규] 버튼과 동일한 경로"를 전제한다. **그 버튼이 존재한 적이
없다.** 생성 폼도, `POST /issues`를 부르는 클라이언트 코드도 없다 — r01a가 생성을 API·CLI로만
만들었고, 화면 쪽 생성은 42개 스토리 어디의 범위도 아니었다.

구현 실패가 아니라 제품에 빈 곳이고, 팔레트 스토리가 그것을 드러냈다. r24a의 다른 13개
인수조건은 닫혔고 이 하나는 열어 둔다 — 없는 버튼을 전제한 조건에 ✅를 붙이면 그것이 이
프로젝트가 계속 고쳐 온 거짓 초록이다.

**채우려면 새 스토리가 필요하다.** 필드가 이슈 스키마 전체(프로젝트·타입·제목·설명·포인트·
라벨·인수조건)이고, S5-D5대로 팔레트는 쓰기를 하지 않으므로 팔레트 쪽은 그 폼을 여는 명령
하나가 된다.

### 열려 있는 것 — 이 스프린트 밖이지만 M5를 닫으려면 필요하다

**OQ1. Q10 — LLM 전송 정책** (r22a·r22b, 13점)
PRD의 유일한 미결이며 §12가 M5의 선결 조건으로 지목했다. 답이 필요한 것: 정제 기능을 지금
만드는가, 만든다면 어느 공급자·모델이며, 비용 상한과 전송 전 사용자 확인을 어떻게 두는가.

## 7. 이번 스프린트에 적용하는 규칙

앞 네 스프린트의 규칙을 그대로 가져가고 하나를 더한다.

- 브랜치는 `feat/<스토리>`, 반영은 PR. 통합 브랜치는 `develop`
- `npm run docs:check`가 CI 필수 단계다
- 테스트는 병렬로 돌린다 · 검증 명령에 파이프를 붙이지 않는다
- 스토리를 열 때 인수조건이 이번 마일스톤에서 검증 가능한지 본다
- 미정을 적기 전에 PRD와 결정 기록을 먼저 뒤진다 — 이번에는 **가장 큰 것이 미결이라는 사실
  자체가 문서에 적혀 있었다**(Q10 선결)
- UI 스토리는 브라우저 확인을 완료 조건에 포함한다
- 거부 경로에 테스트가 없으면 그 인수조건은 닫지 않는다
- 동시성 인수조건은 진짜 동시 요청으로 검증한다
- 재생·집계는 순서를 바꿔 돌려 같은 답이 나오는지 본다
- **(신규) 읽기 전용이라고 적힌 기능은 "안 바뀌었음"을 파일로 확인한다.** 이 스프린트의 세
  스토리 모두 코드 저장소나 도메인 파일을 건드리지 않는다고 약속한다. 약속만 있고 확인이
  없으면 그것은 주장이다
