# 웹 이슈 수정 폼 — 필드 편집과 412 충돌 표시

> `r01c`의 짝이다. `r01b`가 `PUT`/`PATCH /issues/{key}`와 전이표·삭제를 만들었지만 **화면에서
> 제목·설명·포인트·라벨·인수조건을 고칠 방법이 없었다.** 상태는 카드를 끌어 옮길 수 있고(r07b)
> 만들기는 r01c가 채웠는데, 그 사이의 "고치기"만 비어 있었다.
>
> 그리고 이 스토리는 `r01c`보다 어려운 지점이 하나 있다. 수정은 **낙관적 동시성**을 지나야
> 한다 — `If-Match`가 없으면 428이고 어긋나면 412다(§5.4, D15). 412를 "다시 시도하세요"로
> 뭉개면 사람이 방금 쓴 내용을 잃고, 서버가 412에 실어 보내는 **현재 문서·최신 ETag·거부된 값**이
> 쓰이지 않는다.

## 사용자 스토리 (User Story)

> **As a** 제목을 잘못 쓴 걸 이제 알아챈 개발자·PO,
> **I want** 이슈 상세에서 필드를 고쳐 저장하고, 그 사이 다른 사람이 같은 이슈를 바꿨다면
> **무엇이 어떻게 달라졌는지** 보고 결정하기를,
> **so that** CLI로 옮겨 가지 않아도 되고, 남의 변경을 모르고 덮어쓰지도 않는다.

## 인수 조건 (Acceptance Criteria)

### 고치기

- [x] Given 이슈 상세, When [수정]을 누르면, Then 수정 폼이 열리고 **현재 값이 채워진 채** 제목에 포커스가 간다. *(§8)*
- [x] Given 수정 폼, When 필드를 확인하면, Then **제목·설명·포인트·라벨·인수조건**을 고칠 수 있다 — `r01b`가 `PATCH /issues/{key}`에서 받는 것과 같은 집합이다. *(§5.1, R1)*
- [x] Given 상태(`status`), When 수정 폼을 보면, Then **편집 대상이 아니다** — 모든 상태 변경은 전이 엔드포인트를 지나야 하고(S1-D2), 폼이 그것을 우회하면 전이표·claim 결합·게이팅이 한 경로에서만 지켜진다. *(§5.2, §6.1, §6.3)*
- [x] Given 아무것도 고치지 않고 [저장], When 처리하면, Then 요청을 보내지 않고 폼이 닫힌다 — 변경 없는 쓰기는 파일을 건드리지 않아야 하고 미커밋 배지도 움직이지 않는다. *(AC24)*
- [x] Given 제목을 빈 값으로 지우고 [저장], When 처리하면, Then 폼에서 막으며 사유를 보여준다. *(r01c와 같은 원칙)*
- [x] Given 서버가 400을 돌려주는 입력(잘못된 라벨 등), When 응답을 받으면, Then **서버가 준 메시지**를 그 자리에 보여주고 입력이 지워지지 않는다 — 검증 규칙의 사본을 클라이언트에 두지 않는다.
- [x] Given 저장 성공, When 화면을 보면, Then 상세·목록·보드가 갱신되고 폼이 닫힌다.

### 낙관적 동시성 (§5.4, R10)

- [x] Given 수정 요청, When 헤더를 확인하면, Then 상세를 읽을 때 받은 **그 ETag가 `If-Match`로** 실린다. 헤더 없이 보내는 경로가 없다. *(D15 — 428은 클라이언트 버그다)*
- [x] Given 폼을 열어 둔 동안 다른 클라이언트가 같은 이슈를 먼저 고침, When [저장]하면, Then **412**를 받고 폼이 열린 채로 **어떤 필드가 어떻게 달라졌는지**(현재 값 대비 내가 쓴 값)를 보여준다. 서버가 412에 실어 준 `conflicts`를 그대로 쓴다. *(AC8)*
- [x] Given 위 충돌 화면, When 선택지를 보면, Then **[최신 값 불러오기]** 와 **[내 값으로 덮어쓰기]** 둘 다 있고, 어느 쪽도 기본으로 실행되지 않는다 — 자동 병합은 사람이 보지 못한 결정을 대신 내리는 일이다.
- [x] Given 충돌 화면에서 [최신 값 불러오기], When 처리하면, Then 폼이 서버의 현재 값으로 갱신되고 내가 쓴 값은 **버려지기 전에 화면에 남아** 다시 옮겨 적을 수 있다.
- [x] Given 충돌 화면에서 [내 값으로 덮어쓰기], When 처리하면, Then 최신 ETag로 다시 보내 저장된다. 이것이 **명시적 last-write-wins**이며 사람이 선택했다는 점이 D15의 금지와 다르다.
- [x] Given 폼이 열린 동안 아무도 고치지 않음, When [저장]하면, Then 412 없이 저장된다.

### 그 밖의 거부와 표기

- [x] Given `INVALID`로 격리된 이슈, When [수정]을 시도하면, Then **409**와 함께 격리 상태·파일 경로가 표시되고 폼이 열리지 않는다. *(§5.6)*
- [x] Given `issue:edit` 권한이 없는 역할·토큰, When 상세를 보면, Then [수정]이 노출되지 않거나 비활성이다. *(§6.4, AC7)*
- [x] Given 저장 후, When 활동 타임라인을 보면, Then `issue.updated` 이벤트가 **바뀐 필드의 before/after**와 함께 남고 actor가 사람으로 표기된다. *(§9 N7, R14)*
- [x] Given 폼이 열림, When `Esc`를 누르면, Then 폼이 닫히고 포커스가 열기 직전 요소로 돌아간다. Tab 포커스가 밖으로 새지 않는다. *(r24a·r01c와 같은 규약)*
- [x] Given 라이트/다크 테마, When 폼과 충돌 화면을 열면, Then 두 테마 모두에서 기존 규약으로 렌더되고 의존성 0개 바닐라를 유지한다. *(S2-D1)*
- [x] Given 네트워크가 없는 환경, When 폼으로 이슈를 고치면, Then 정상 동작한다. *(N4)*

## 범위 밖 (Out of Scope)

- 상태 전이 — 전이 엔드포인트와 드래그(`r07b`)가 담당한다. 폼은 상태를 만지지 않는다
- 삭제 — `r01b`가 API를 만들었고 화면 쪽 삭제는 별 스토리다(파괴적 행위라 확인 절차 설계가 따로 필요하다)
- 부모·스프린트·순서 변경 — `r02a`·`r06`·`r03`의 화면 절반이며 각각 별 스토리다
- 3-way 자동 병합 — §5.4가 "3-way diff는 클라이언트가 자기 base로 계산한다"고 했지만, 이 스토리는 **충돌을 보여주고 사람이 고르게** 한다. 자동 병합은 사람이 보지 못한 결정을 대신 내리는 일이다
- 코멘트 작성 UI — R19의 화면 절반이며 별 스토리다

> **만들다 나온 결함(2026-07-30).** 격리된 이슈가 하나 있으면 **새 이슈를 아예 만들 수 없었다.**
> 전체 재빌드 후에는 파싱 실패한 파일의 `issues` 행이 없어 `allocateKey`가 그 번호를 다시 냈고,
> 파일 존재 검사가 그것을 막아 모든 생성이 `E_KEY_COLLISION`으로 떨어졌다. 깨진 파일 하나가
> 보드 전체의 생성을 막는 상태였다. `index_errors`의 경로에서 키를 읽어 반영하도록 고쳤다 —
> 이번 세션에서 같은 뿌리(재빌드 후 행 없음)로 세 번째 발견된 결함이다.
