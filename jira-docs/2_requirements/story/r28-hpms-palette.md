# 배색을 HPMS 디자인 시스템에 맞춘다

> 화면은 다 만들어졌는데 색이 제각각이었다. **고유 색 116개**가 CSS 곳곳에 하드코딩돼 있었고,
> 그 각각이 손으로 쓴 다크 모드 짝을 갖고 있었다 — 그리고 그중 하나(글자색)는 아예 쓰이지
> 않아서, 다크 패널에 검은 글자가 몇 달간 찍혔다(S6-D5에서 드러났다).
>
> 이건 취향의 문제가 아니라 **구조의 문제**다. 색을 컴포넌트가 정하면 컴포넌트 수만큼 진실이
> 생기고, 하나를 빠뜨려도 아무도 모른다.
>
> `hpms-system`이 이미 이 문제를 푼 규칙을 갖고 있으므로 그것을 가져온다. 값도 그쪽 SSOT에서
> **복사**한다 — 다시 짜면 두 제품이 조금씩 다른 색이 되고, 그게 지금 상태다.

## 사용자 스토리 (User Story)

> **As a** 이 도구와 HPMS를 오가며 쓰는 사람,
> **I want** 두 화면이 같은 색 규칙을 따르기를,
> **so that** 도구를 바꿀 때마다 눈이 다시 적응하지 않고, 색이 무엇을 뜻하는지 한 번만 배운다.

## 인수 조건 (Acceptance Criteria)

### 토큰 (§1.2)

- [x] Given `app.css`, When 훑으면, Then **하드코딩된 색이 하나도 없다.** 모든 색은 `var(--토큰)`이거나 토큰의 `color-mix`다.
- [x] Given 토큰 값, When HPMS의 `theme.css`와 대조하면, Then 시맨틱 토큰이 **같은 OKLCH 값**이다 — 다시 계산하지 않고 복사한다.
- [x] Given 라이트와 다크, When 토큰 집합을 비교하면, Then **양쪽이 같은 이름을 정의**한다. 한쪽에만 있는 토큰은 뒤집히지 않는 색이다.
- [x] Given 다크 모드, When CSS를 보면, Then 블록이 **하나**다. 컴포넌트별 다크 오버라이드가 글자색을 잊게 만든 원인이었다.

### 배색 (§5.1)

- [x] Given 화면 전체, When 색을 보면, Then **중립 회색 베이스에 블루 강조 하나**다. 초록 일색이던 것을 바꾼다.
- [x] Given 종류로 구분되는 것(주체 배지 등), When 보면, Then 심각도 토큰이 아니라 **카테고리 팔레트**(`--chart-*`)에서 온다 — 그중 어느 것도 오류가 아니다.

### 표면 (§6.3)

- [x] Given 카드형 표면(이슈 카드·로그인 카드·컬럼·설정·코멘트 등), When 보면, Then **그림자가 없다.** 표면은 `border`로 구분한다.
- [x] Given 그림자가 남은 곳, When 확인하면, Then 드로어·팔레트·토스트뿐이다 — **떠 있음이 뜻을 갖는** 곳이다. 포커스 링과 상태 점은 링이지 리프트가 아니다.
- [x] Given 반경, When 보면, Then `--radius` 하나에서 파생된 값만 쓴다.

### 읽힘

- [x] Given 라이트 모드, When 모든 배지·칩의 대비를 재면, Then **4.5:1 이상**이다.
- [x] Given 다크 모드, When 같은 것을 재면, Then **4.5:1 이상**이다.
- [x] Given 본문, When 재면, Then 두 테마 모두 19:1 안팎이다.

### 그대로인 것

- [x] Given 이 변경, When 셀렉터 목록을 비교하면, Then **사라진 셀렉터가 없다.** 색·반경·그림자 외의 규칙은 건드리지 않는다.
- [x] Given 의존성, When 확인하면, Then **여전히 0개다.** Tailwind를 들이지 않고 `var()`와 `color-mix()`로 쓴다.

> **만들다 나온 것(2026-08-05).** **역할색을 옅은 배경 위 글자로 그대로 쓰면 대비가 무너진다.**
> HPMS에서 `--warning`·`--chart-*`는 *채움색*이고 글자는 `--*-foreground`인데, 나는 그 색을
> 옅은 틴트 위 글자로 얹었다. 재 보니 `--warning`이 자기 틴트 위에서 **1.9:1**, `--chart-4`가
> **1.6:1**이었다 — 규칙은 따랐는데 읽히지 않는 화면이 나왔다.
>
> `--on-*-soft` 토큰으로 고쳤다. 역할색을 `--foreground` 쪽으로 섞으면 라이트에서는 검정 쪽,
> 다크에서는 흰색 쪽으로 움직이므로 **한 선언이 두 테마에서 모두 읽힌다.** 13곳이 이 토큰을 쓴다.
>
> **검증도 두 번 틀렸다.** 대비를 재려고 `getComputedStyle`의 문자열을 파싱했는데 값이
> `oklch()`라 파서가 1:1을 돌려줬다 — 캔버스에 실제로 칠해 픽셀을 읽도록 바꿨다. 그리고
> 일부러 깨뜨린 실험 셋이 "통과"로 보였는데, `grep '✖ 패턴'`이 테스트 이름 **앞부분**까지
> 요구해서 실패 줄을 못 읽은 것이었다. 실험이 통과하면 실험부터 의심해야 한다 — 이번 세션에서
> 세 번째다.

## 범위 밖 (Out of Scope)

- Tailwind·shadcn 도입 — S2-D1이 의존성 0개를 지킨다. 가져오는 것은 **규칙과 값**이지 스택이 아니다
- 레이아웃 규칙(§6.1 툴바 위치 등) — 이번은 배색만이다. 레이아웃은 별 스토리다
- 타이포그래피 스케일 — HPMS가 Tailwind 유틸리티로 정의하므로 그대로 옮길 수 없다
- 라이트/다크 수동 전환 — 지금은 OS 설정을 따른다
