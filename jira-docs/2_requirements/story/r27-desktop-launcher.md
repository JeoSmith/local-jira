# 데스크톱 런처 — 아이콘을 누르면 창이 뜨고 보드가 열린다

> 지금 보드를 열려면 터미널에서 `localjira serve`를 치고 브라우저에 주소를 넣어야 한다. 매일
> 쓰는 도구로는 성가시고, "로컬에서 도는 프로그램"이라기보다 "직접 띄우는 스크립트"에 가깝다.
>
> **의존성 0개(S2-D1)를 깨지 않고** 이걸 해결하는 것이 이 스토리의 전부다. Electron이나 Tauri를
> 쓰면 창은 쉽게 얻지만, 그 순간 이 제품은 런타임 하나를 배포·갱신·감사해야 하는 물건이 된다.
> UI를 바닐라로 쓰고 테스트를 `node:test`로 쓴 이유가 사라진다.

## 사용자 스토리 (User Story)

> **As a** 보드를 매일 여는 사람,
> **I want** 독에 있는 아이콘을 눌러 창 하나로 보드를 보기를,
> **so that** 터미널을 열어 명령을 치고 주소를 붙여넣는 세 단계를 매번 반복하지 않는다.

## 인수 조건 (Acceptance Criteria)

### 만들기

- [x] Given 보드가 있는 저장소, When `node scripts/make-app.ts --repo <경로>`를 실행하면, Then `.app` 번들이 만들어지고 macOS가 앱으로 인식하는 구성(Info.plist·실행 권한 있는 실행 파일)을 갖춘다.
- [x] Given `.localjira`가 없는 디렉터리, When 빌드를 시도하면, Then **아무것도 쓰지 않고** 거부하며 `localjira init`을 안내한다 — 빈 창을 세 번 클릭한 뒤에 알게 하지 않는다.
- [x] Given `--repo`를 주지 않음, When 실행하면, Then 거부한다. 어느 보드를 열지에 기본값은 없다.
- [x] Given 빌드 결과, When 아이콘을 보면, Then 생성된 `AppIcon.icns`가 들어 있고 중간 산출물(`.iconset`)은 남지 않는다.
- [x] Given `iconutil`이 없는 환경(비 macOS), When 빌드하면, Then 아이콘만 건너뛰고 나머지는 정상 생성되며 그 사실을 말한다.

### 실행

- [x] Given 서버가 떠 있지 않은 상태, When 앱을 열면, Then 서버가 뜨고 **탭·주소창 없는 창**에 보드가 표시된다.
- [x] Given 앱이 실행 중, When **독과 ⌘Tab을 보면**, Then **이 앱의 이름과 아이콘**으로 뜬다 — 브라우저 이름이 아니다.
- [x] Given 네이티브 창, When 메뉴 막대를 보면, Then ⌘Q·⌘C·⌘V·⌘R이 동작한다 — 웹 뷰의 복사·붙여넣기는 편집 메뉴에서 온다.
- [x] Given `swiftc`가 없는 기계, When 빌드하면, Then 브라우저 앱 모드로 물러나고 **빌드가 어느 쪽을 만들었는지 말한다.**
- [x] Given 앱을 종료(⌘Q)하면, When 확인하면, Then **앱이 띄운 서버도 함께 멈춘다.** 창을 닫아도 앱이 남는 것은 맥 표준 동작이고, 종료가 정리 지점이다.
- [x] Given 터미널에서 이미 `localjira serve`가 돌고 있음, When 앱을 열면, Then **새로 띄우지 않고 그 서버에 붙으며**, 앱을 종료해도 그 서버는 죽지 않는다 — 내가 띄우지 않은 것을 내가 끄지 않는다.
- [x] Given 서버가 뜨지 못함(포트 사용 중·보드 손상), When 앱을 열면, Then 알림으로 실패를 알리고 로그 위치를 말한다. 빈 창을 보여주지 않는다.
- [x] Given Chromium 계열 브라우저가 없음, When 앱을 열면, Then 기본 브라우저로 보드를 열고, **창에 묶인 수명이 없으므로 서버를 죽이지 않는다.**

> **만들다 나온 것(2026-08-03).** 아이콘의 J가 통째로 사라져 "L I"로 나왔다. 갈고리와 윗줄을
> `unit * 8.4`에서 시작하도록 그렸는데 512px에서 그게 `268.8`이고, **Buffer에 소수 인덱스로
> 쓰면 오류 없이 그냥 버려진다.** 세로줄만 좌표가 정수로 떨어져 살아남은 것이다.
>
> 이 결함을 잡으려고 쓴 **첫 테스트도 틀렸다.** 완성된 PNG에서 잉크 색 바이트를 찾았는데 PNG는
> 압축돼 있어서, 멀쩡한 아이콘에도 실패했다. 픽셀 버퍼를 인코딩 전에 보도록 고쳤다.
>
> 그러고도 **두 번째 테스트가 약했다.** "오른쪽 절반에 잉크가 있는가"로 봤더니, J의 세로줄만
> 남은 깨진 아이콘도 통과했다 — 화면에 "L I"가 떠 있는데 단언은 참이었다. 반올림을 되돌려
> 실험했을 때 통과해 버려서 알았다. 지점을 지목하는 방식(갈고리 자리, 윗줄 자리)으로 바꾸니
> 그제야 잡힌다.
>
> 한 결함을 잡는 데 검사를 세 번 고쳤다. 그릴 수 있는 것은 틀릴 수도 있고, **틀린 것을 못 보는
> 검사는 없는 것과 같다.**

> **되돌린 결정(2026-08-03).** 처음 만든 것은 **데스크톱 앱이 아니었다.** Chromium의 `--app`
> 모드로 창을 띄웠는데, Finder에서는 이름도 아이콘도 맞지만 **실행하면 독에 "Google Chrome"이
> 뜬다.** ⌘Tab도 그렇다. 브라우저를 여는 바로가기지 앱이 아니었고, 빌드 출력은 어느 쪽인지
> 말하지도 않았다.
>
> 사용자가 **"그렇게 만든 거 맞냐"**고 물어 확인하다 드러났다. 인수조건에 "탭·주소창 없는 창"만
> 적어 두고 **독에 무엇으로 뜨는지는 묻지 않은** 탓이다 — 화면에 보이는 것을 적었지 정체를
> 적지 않았다.
>
> `WKWebView`를 `swiftc`로 컴파일해 진짜 앱으로 바꿨다. 100KB 바이너리에 시스템 프레임워크만
> 쓰므로 의존성은 여전히 0개다. 옛 경로는 `swiftc`가 없을 때의 폴백으로 남기고, **빌드가 어느
> 쪽을 만들었는지 말하게** 했다.

## 범위 밖 (Out of Scope)

- Windows·Linux 런처 — `.app`은 macOS 형식이다. 다른 OS는 각자의 방식이 필요하고 수요가 확인되면 연다
- 코드 서명·공증 — 배포하지 않고 자기 기계에서 만들어 쓰는 것이 전제다. 남에게 나눠 줄 때 필요해진다
- 자동 업데이트 — 번들이 저장소의 `src/cli.ts`를 가리키므로 `git pull`이 곧 업데이트다
- 네이티브 메뉴·트레이 아이콘 — 창 하나가 목적이고, 그 이상은 런타임이 필요하다
- 여러 보드를 한 앱에서 — 보드마다 앱을 만든다. `--name`으로 이름을 달리 준다

> ⚠ 미정: 앱을 `~/Applications`에 자동 설치할지. 지금은 `--out`으로 만들고 사람이 옮긴다 —
> 빌드 스크립트가 묻지도 않고 홈 디렉터리에 쓰는 것은 놀라운 일이다.
