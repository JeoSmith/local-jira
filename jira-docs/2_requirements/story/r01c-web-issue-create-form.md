# 웹 이슈 생성 폼 — 툴바 [신규] 버튼과 생성 경로

> R1의 **화면 절반**이다. `r01a`가 `POST /issues`와 파일 형식을, `r01b`가 수정·전이·삭제를
> 만들었지만 **웹에서 이슈를 만드는 길은 어느 스토리에도 없었다.** r24a(커맨드 팔레트)를 만들다
> 드러났다 — 그 인수조건이 "툴바 우측의 [신규] 버튼과 동일한 경로"를 전제했는데 그 버튼이
> 존재한 적이 없다.
>
> 빈 곳은 스토리 지도만이 아니다. **PRD §8의 화면 목록에도 생성 affordance가 없다** — 백로그·
> 보드·상세·스프린트·정제·설정 여섯 화면이 전부 보기 위한 것으로 서술돼 있다. r24a의 그
> 인수조건은 다른 프로젝트의 규약(`HPMS design.md §6.1`)을 인용해 없는 버튼을 가정했다.

## 사용자 스토리 (User Story)

> **As a** 이슈를 떠올린 순간에 적어 두려는 개발자·PO,
> **I want** 보고 있는 화면에서 [신규]를 눌러 이슈를 만들기를,
> **so that** 터미널로 옮겨 가 CLI를 치거나 curl을 쓰지 않고, 성공 지표인 "이슈 1건 생성 ≤ 30초"가
> 실제로 달성 가능해진다(§11).

## 인수 조건 (Acceptance Criteria)

### 만들기

- [x] Given 백로그·보드 어느 화면이든, When 툴바의 [신규]를 누르면, Then 생성 폼이 열리고 첫 입력(제목)에 포커스가 간다. *(§8)*
- [x] Given 생성 폼, When 필드를 확인하면, Then **프로젝트·타입·제목·설명·포인트·라벨·인수조건**을 입력할 수 있다 — `r01a`가 `POST /issues`에서 받는 것과 같은 집합이다. *(§5.1, R1)*
- [x] Given 제목만 채우고 [만들기], When 처리하면, Then 이슈가 생성되고 `BACKLOG`로 목록에 나타난다. 나머지 필드는 선택이다. *(S1-D1 — 생성 시 상태는 항상 `BACKLOG`)*
- [x] Given 프로젝트가 하나뿐인 보드, When 폼을 열면, Then 프로젝트가 그 값으로 미리 선택되어 있다 — 선택지가 하나인 질문을 사람에게 묻지 않는다.
- [x] Given 여러 프로젝트가 있고 백로그 화면에 프로젝트 필터가 걸린 상태, When 폼을 열면, Then 그 프로젝트가 미리 선택된다. 보고 있던 맥락이 기본값이다.
- [x] Given 제목이 빈 상태, When [만들기]를 누르면, Then 서버에 요청하지 않고 폼에서 막으며 사유를 보여준다. 왕복해서 400을 받는 경험을 만들지 않는다. *(r24a AC6과 같은 원칙)*
- [x] Given 라벨 입력에 공백이나 쉼표가 든 값, When 제출하면, Then `requireLabels`와 **같은 규칙**으로 폼에서 거부되고 그 이유가 표시된다 — 규칙의 사본이 아니라 서버 오류를 그대로 보여주는 방식이어야 어긋나지 않는다.
- [x] Given 만들기 성공, When 화면을 보면, Then 목록·보드가 새 이슈를 포함해 갱신되고 폼이 닫힌다.

### 쓰기 경로

- [x] Given [만들기], When 네트워크를 확인하면, Then `POST /issues` **하나만** 호출된다 — 화면이 별도의 쓰기 규칙을 갖지 않는다.
- [x] Given 만들기 요청, When 헤더를 확인하면, Then `Idempotency-Key`가 실려 있어 더블클릭·재시도가 이슈를 두 번 만들지 않는다. *(§5.4, r15)*
- [x] Given 같은 폼을 두 번 빠르게 제출, When 결과를 확인하면, Then 이슈가 1건이고 `git status`에도 파일 1개만 잡힌다. *(AC18)*
- [x] Given `issue:edit` scope가 없는 토큰으로 로그인한 세션 또는 그 권한이 없는 역할, When 툴바를 보면, Then [신규]가 노출되지 않거나 비활성이다 — 눌러서 403을 받는 경험을 만들지 않는다. *(§6.4, AC7)*
- [x] Given 서버가 400을 돌려주는 입력(예: 없는 부모 uid), When 응답을 받으면, Then 폼이 열린 채로 서버가 준 메시지를 그 자리에 보여주고 입력이 지워지지 않는다.

### 키보드와 표기

- [x] Given 어느 화면이든, When 팔레트에서 "새 이슈"를 실행하면, Then **같은 폼이 열린다** — 팔레트는 쓰기를 하지 않고 이 경로를 여는 것까지다. *(S5-D5)*
- [x] Given 폼이 열림, When `Esc`를 누르면, Then 폼이 닫히고 포커스가 열기 직전 요소로 돌아간다. Tab 포커스가 폼 밖으로 새지 않는다(포커스 트랩). *(r24a와 같은 규약)*
- [x] Given 라이트/다크 테마, When 폼을 열면, Then 두 테마 모두에서 기존 화면과 같은 규약으로 렌더된다. 의존성 0개 바닐라를 유지한다. *(S2-D1)*
- [x] Given 만들어진 이슈, When 카드와 타임라인을 보면, Then `created_by_kind=human`이고 사람이 만든 것으로 표기된다. *(§5.1, §8)*
- [x] Given 네트워크가 없는 환경, When 폼으로 이슈를 만들면, Then 정상 동작한다 — 로컬 서버만 쓴다. *(N4)*

## 범위 밖 (Out of Scope)

- 이슈 **수정** 폼 — `r01b`가 API를 만들었고 화면 쪽 수정은 이 스토리의 범위가 아니다(같은 빈 곳이 남아 있다는 사실은 여기 적어 둔다)
- 부모 지정 UI(계층) — uid를 사람이 붙여넣는 형태 이상은 `r02a`의 화면 절반이며 별 스토리다
- 스프린트 배정 — `r06`
- 백로그 순서 지정 — `r03`
- 일괄 생성·CSV 임포트 — D6이 임포트를 비목표로 확정했다
