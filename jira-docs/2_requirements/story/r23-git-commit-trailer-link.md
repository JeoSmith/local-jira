# git 통합 — 커밋 트레일러 스캔으로 커밋 자동 연결

## 사용자 스토리 (User Story)

> **As a** 개발자(및 에이전트를 감독하는 사람),
> **I want** 커밋 메시지에 `Issue: LJ-12` 트레일러만 달아두면 그 커밋이 해당 이슈에 자동으로 붙기를,
> **so that** "이 이슈를 누가 어디까지 했나"가 커밋 메시지에만 남아 끊기는 문제(P2)를 손으로 링크를 거는 수고 없이 메운다.

## 인수 조건 (Acceptance Criteria)

- [x] Given 코드 브랜치에 `Issue: LJ-12` 트레일러를 가진 커밋, When 스캔이 수행되면, Then 그 커밋(해시·요약·author·커밋 시각)이 `LJ-12` 이슈에 연결되어 이슈 상세에서 보인다. *(§7 R23, §8 이슈 상세)*
- [x] Given 스캔 실행, When 어떤 히스토리를 읽는지 확인하면, Then **코드 저장소 쪽 브랜치 히스토리**를 읽으며, 보드 데이터가 사는 `localjira/data` 브랜치(= `.localjira/` worktree)의 커밋은 스캔 대상이 아니다. *(D1)*
- [x] Given `LJ-13`이 `LJ-14`로 재키잉되어 `former_keys: [LJ-13]`을 가진 이슈, When `Issue: LJ-13` 트레일러 커밋을 스캔하면, Then 그 커밋이 **현재 키 `LJ-14`** 이슈에 연결된다 — 옛 표시 키로 쓴 트레일러가 죽지 않는다. *(D3, R26)*
- [x] Given `LJ-13`을 **현재 키로** 가진 이슈와 `former_keys`로만 가진 이슈가 동시에 존재, When `Issue: LJ-13` 트레일러를 해석하면, Then **원 소유자(현재 키 보유자) 우선** 규칙을 따른다. *(AC25)*
- [x] Given 스캔 실행, When 코드 저장소의 상태를 확인하면, Then 어떤 커밋·태그·브랜치·체크아웃도 만들어지지 않는다 — **읽기 전용 스캔**이다. *(D4)*
- [x] Given 스캔 실행, When `git -C .localjira status`를 보면, Then 서비스가 스스로 커밋·푸시하지 않는다. 연결 결과로 도메인 파일이 바뀌면 미커밋 배지 건수만 증가한다. *(D4, R25)*
- [x] Given 커밋 메시지 **본문 자유 텍스트**에 `LJ-12`가 언급된 커밋(트레일러 없음), When 스캔하면, Then 자동 연결하지 않는다 — R23의 대상은 트레일러다.
- [x] Given 이미 연결된 커밋, When 스캔을 다시 돌리면, Then 같은 연결이 중복 생성되지 않는다(멱등).
- [x] Given 커밋 연결이 기록됨, When 활동 타임라인을 보면, Then `actor_kind=system`으로 남고 **커밋 author를 인증된 actor로 간주하지 않는다** — 커밋 정보는 참고 정보로만 취급한다. *(§5.7)*
- [x] Given 에이전트가 수행한 작업의 AgentRun과 같은 이슈에 스캔으로 연결된 커밋이 함께 있음, When 이슈 상세를 보면, Then 둘이 구분되어 표시된다(run이 보고한 `commits[]` vs 트레일러 스캔으로 붙은 커밋). *(§5.1 AgentRun, §8)*
- [x] Given 대상 디렉터리가 git 저장소가 아니거나 git 실행 파일이 없음, When 서버를 기동하면, Then 커밋 연결 기능만 비활성화되고 나머지 기능은 정상 동작한다.
- [x] Given 스캔 대상 이슈가 `INVALID`로 격리된 상태, When 그 이슈를 가리키는 트레일러를 만나면, Then 격리된 엔티티의 변경은 복구 전까지 차단되므로 연결도 보류되고 사유가 표시된다. *(§5.6)*

> 결정됨(S5-D1): 연결은 **인덱스에만** 둔다. frontmatter에 쓰면 스캔마다 도메인 파일이 바뀌고,
> D4에 따라 그 변경은 사람이 커밋해야 하므로 **자기가 하지 않은 변경을 커밋**하게 된다. 파일
> SoT가 요구하는 "재빌드로 복원 가능"은 여기서 **git 히스토리 자체가 원본**이라는 것으로
> 충족된다 — 이 도구가 지울 수도 바꿀 수도 없는 기록이고, 다시 스캔하면 같은 연결이 나온다.
> `AgentRun.commits[]`와는 `source`로 구분해 표시한다.
> 결정됨(S5-D2): 트리거는 **사람이 누르거나 기동 시 한 번**. 주기 폴링은 이 도구가 남의 저장소를
> 상시 들여다보게 만들고, git 훅은 사용자의 `.git/hooks`를 이 도구가 고치는 일이다. 범위는
> 현재 HEAD의 최근 **1,000커밋**이며 설정으로 올릴 수 있다. 스캔은 `index:rebuild` 권한이고
> 어떤 토큰 scope도 닿지 못한다.
> 결정됨(S5-D3): `Issue:` 하나만, 대소문자 무관, 한 커밋의 여러 줄은 **전부 연결**한다. 첫 줄만
> 보면 두 번째 줄을 쓴 사람이 왜 안 붙는지 알 수 없다.
> 결정됨(S5-D4): 없는 키는 **미해결 참조로 보류**하고 다음 스캔에서 다시 해석한다. 트레일러를
> 먼저 쓰고 이슈를 나중에 만드는 순서가 있을 수 있고, 조용히 버리면 다시 붙을 기회가 없다.
> rebase·amend로 히스토리에 없어진 연결은 재스캔 때 **정리**한다.
> 결정됨: 스캔 대상은 `.localjira`를 품은 그 저장소다. remote·서브모듈은 추측이고, 틀린 추측은
> 아무도 묻지 않은 저장소의 커밋을 붙인다.
> 결정됨: 감사에는 **스캔 1건당 이벤트 1건**을 `actor_kind=system`으로 남긴다. 링크마다 남기면
> 천 개의 커밋이 같은 말을 천 줄 쓴다. §5.7대로 커밋 author는 인증된 주체가 아니므로 actor는
> 스캔 자신이다.
> 결정됨: 성능은 스캔 상한(1,000커밋)으로 묶는다 — 수만 커밋 저장소에서 매 기동마다 전량을
> 읽을 수 없고, 트레일러가 달린 커밋은 최근작일 가능성이 압도적이다.

## 범위 밖 (Out of Scope)

- 커밋 연결에 따른 **이슈 상태 자동 전이** — PRD는 커밋으로 상태를 바꾸라고 요구하지 않는다(전이는 §5.2 표 + 명시적 명령).
- 서비스가 커밋·푸시하는 동작 — 하지 않는다(D4).
- 미커밋 변경 건수·마지막 push 시각 배지 → R25
- AgentRun이 스스로 보고하는 `commits[]` 등록 경로 → R17
- 브랜치·PR·코드 리뷰 연동, diff 뷰어, CI 상태 표시
- `.localjira/` 데이터 브랜치의 pull/push 동기화 → D2 (사람이 수행)
- 커밋 author를 로컬 계정에 매핑해 인증 주체로 쓰는 것 — §5.7이 명시적으로 금지한다
