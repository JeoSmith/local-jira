# git 통합 — 커밋 트레일러 스캔으로 커밋 자동 연결

## 사용자 스토리 (User Story)

> **As a** 개발자(및 에이전트를 감독하는 사람),
> **I want** 커밋 메시지에 `Issue: LJ-12` 트레일러만 달아두면 그 커밋이 해당 이슈에 자동으로 붙기를,
> **so that** "이 이슈를 누가 어디까지 했나"가 커밋 메시지에만 남아 끊기는 문제(P2)를 손으로 링크를 거는 수고 없이 메운다.

## 인수 조건 (Acceptance Criteria)

- [ ] Given 코드 브랜치에 `Issue: LJ-12` 트레일러를 가진 커밋, When 스캔이 수행되면, Then 그 커밋(해시·요약·author·커밋 시각)이 `LJ-12` 이슈에 연결되어 이슈 상세에서 보인다. *(§7 R23, §8 이슈 상세)*
- [ ] Given 스캔 실행, When 어떤 히스토리를 읽는지 확인하면, Then **코드 저장소 쪽 브랜치 히스토리**를 읽으며, 보드 데이터가 사는 `localjira/data` 브랜치(= `.localjira/` worktree)의 커밋은 스캔 대상이 아니다. *(D1)*
- [ ] Given `LJ-13`이 `LJ-14`로 재키잉되어 `former_keys: [LJ-13]`을 가진 이슈, When `Issue: LJ-13` 트레일러 커밋을 스캔하면, Then 그 커밋이 **현재 키 `LJ-14`** 이슈에 연결된다 — 옛 표시 키로 쓴 트레일러가 죽지 않는다. *(D3, R26)*
- [ ] Given `LJ-13`을 **현재 키로** 가진 이슈와 `former_keys`로만 가진 이슈가 동시에 존재, When `Issue: LJ-13` 트레일러를 해석하면, Then **원 소유자(현재 키 보유자) 우선** 규칙을 따른다. *(AC25)*
- [ ] Given 스캔 실행, When 코드 저장소의 상태를 확인하면, Then 어떤 커밋·태그·브랜치·체크아웃도 만들어지지 않는다 — **읽기 전용 스캔**이다. *(D4)*
- [ ] Given 스캔 실행, When `git -C .localjira status`를 보면, Then 서비스가 스스로 커밋·푸시하지 않는다. 연결 결과로 도메인 파일이 바뀌면 미커밋 배지 건수만 증가한다. *(D4, R25)*
- [ ] Given 커밋 메시지 **본문 자유 텍스트**에 `LJ-12`가 언급된 커밋(트레일러 없음), When 스캔하면, Then 자동 연결하지 않는다 — R23의 대상은 트레일러다.
- [ ] Given 이미 연결된 커밋, When 스캔을 다시 돌리면, Then 같은 연결이 중복 생성되지 않는다(멱등).
- [ ] Given 커밋 연결이 기록됨, When 활동 타임라인을 보면, Then `actor_kind=system`으로 남고 **커밋 author를 인증된 actor로 간주하지 않는다** — 커밋 정보는 참고 정보로만 취급한다. *(§5.7)*
- [ ] Given 에이전트가 수행한 작업의 AgentRun과 같은 이슈에 스캔으로 연결된 커밋이 함께 있음, When 이슈 상세를 보면, Then 둘이 구분되어 표시된다(run이 보고한 `commits[]` vs 트레일러 스캔으로 붙은 커밋). *(§5.1 AgentRun, §8)*
- [ ] Given 대상 디렉터리가 git 저장소가 아니거나 git 실행 파일이 없음, When 서버를 기동하면, Then 커밋 연결 기능만 비활성화되고 나머지 기능은 정상 동작한다.
- [ ] Given 스캔 대상 이슈가 `INVALID`로 격리된 상태, When 그 이슈를 가리키는 트레일러를 만나면, Then 격리된 엔티티의 변경은 복구 전까지 차단되므로 연결도 보류되고 사유가 표시된다. *(§5.6)*

> ⚠ 미정: **스캔 트리거** — 수동 버튼인지, 주기 폴링인지, git 훅인지, `.git/HEAD`·`index` 변화 감지(§5.5)에 얹는지.
> ⚠ 미정: **스캔 범위** — 어떤 브랜치들을 볼지(현재 HEAD만 vs 전체 로컬 브랜치 vs 원격 추적 브랜치), 기간·최대 커밋 수, 최초 1회 전체 히스토리 스캔의 처리 방식.
> ⚠ 미정: **연결 정보의 저장 위치** — 이슈 파일 frontmatter에 남길지(그러면 스캔이 도메인 파일을 쓰게 되어 미커밋 배지가 계속 증가한다), 인덱스에만 둘지(그러면 파일 SoT 원칙상 재빌드로 복원 가능해야 한다). §5.1의 `Issue` 필드에는 커밋 목록이 없고 `AgentRun.commits[]`만 있다.
> ⚠ 미정: **트레일러 키 이름** — `Issue:` 고정인지 설정 가능한지, 대소문자 구분 여부, 복수형(`Issues:`)·다중 키 허용 여부.
> ⚠ 미정: 한 커밋에 **트레일러 라인이 여러 개**일 때(여러 이슈에 모두 연결 vs 첫 줄만) — PRD 미규정.
> ⚠ 미정: **존재하지 않는 키**(`LJ-999`)를 가리키는 트레일러의 처리 — 무시할지, 미해결 참조로 표시하고 나중에 그 키가 생기면 다시 붙일지.
> ⚠ 미정: 다중 remote·서브모듈·모노레포에서 **어느 저장소를 스캔 대상으로 삼을지** 판별 규칙.
> ⚠ 미정: rebase·amend·force push로 **커밋 해시가 바뀐** 경우의 처리(고아 연결 정리 여부).
> ⚠ 미정: 커밋 연결이 §9 N7 **감사 범위**의 이벤트인지 — N7 목록에 커밋 연결이 없다.
> ⚠ 미정: 대형 히스토리(수만 커밋) 스캔의 성능 기준 — §9 NFR에 해당 항목이 없다.

## 범위 밖 (Out of Scope)

- 커밋 연결에 따른 **이슈 상태 자동 전이** — PRD는 커밋으로 상태를 바꾸라고 요구하지 않는다(전이는 §5.2 표 + 명시적 명령).
- 서비스가 커밋·푸시하는 동작 — 하지 않는다(D4).
- 미커밋 변경 건수·마지막 push 시각 배지 → R25
- AgentRun이 스스로 보고하는 `commits[]` 등록 경로 → R17
- 브랜치·PR·코드 리뷰 연동, diff 뷰어, CI 상태 표시
- `.localjira/` 데이터 브랜치의 pull/push 동기화 → D2 (사람이 수행)
- 커밋 author를 로컬 계정에 매핑해 인증 주체로 쓰는 것 — §5.7이 명시적으로 금지한다
