# 키보드 단축키와 커맨드 팔레트

## 사용자 스토리 (User Story)

> **As a** 하루에도 여러 번 이슈를 오가는 개발자·PO,
> **I want** 키보드만으로 팔레트를 열어 이슈를 찾아가고 자주 쓰는 명령을 실행하기를,
> **so that** 이슈 1건 생성·조회에 드는 시간이 마우스로 화면을 헤매는 비용에 잡아먹히지 않는다(성공 지표: 이슈 1건 생성 ≤ 30초).

## 인수 조건 (Acceptance Criteria)

- [x] Given 백로그·보드·이슈 상세·스프린트·설정 중 어느 화면이든, When 팔레트 단축키를 누르면, Then 커맨드 팔레트가 열리고 검색 입력에 포커스가 간다. *(§8 화면 목록)*
- [x] Given 팔레트가 열림, When 텍스트를 입력하면, Then **이슈 결과**(표시 키·제목·본문 전문 검색)와 **명령 결과**(화면 이동, 신규 이슈, 필터 적용)가 서로 구분된 그룹으로 표시된다. *(R4 FTS5)*
- [x] Given 팔레트에서 이슈를 선택, When Enter를 누르면, Then `/issues/:key`로 이동한다. *(§8)*
- [x] Given 재키잉으로 `LJ-13`을 `former_keys`에 갖게 된 이슈, When 팔레트에 `LJ-13`을 입력하면, Then 현재 키 보유 이슈와 옛 키 보유 이슈가 **구분되어** 결과에 나온다. *(AC25, R26)*
- [x] Given 5,000건 데이터셋, When 팔레트에서 검색어를 입력하면, Then 검색·필터 API가 **p95 ≤ 300ms**를 만족한다. *(N1, AC13)*
- [x] Given 권한이 없는 사용자(예: `issue:delete`가 없는 토큰·역할), When 팔레트를 열면, Then 실행할 수 없는 명령은 노출되지 않거나 비활성화된다 — 눌러서 403을 받는 경험을 만들지 않는다. *(§6.4, AC7)*
- [x] Given 제목·설명 등 **텍스트 입력 필드에 포커스**가 있음, When 단일 문자 단축키에 해당하는 글자를 입력하면, Then 단축키가 발동하지 않고 글자가 그대로 입력된다.
- [x] Given 팔레트가 열림, When `ESC`를 누르면, Then 팔레트가 닫히고 포커스가 열기 직전 요소로 돌아간다.
- [x] Given 팔레트가 열림, When 키보드만으로 조작하면, Then 위/아래로 항목을 이동하고 Enter로 실행할 수 있으며, Tab 포커스가 팔레트 밖으로 새지 않는다(포커스 트랩).
- [ ] Given 백로그·보드 리스트 화면, When 단축키로 신규 이슈를 만들면, Then 툴바 우측(`ml-auto`)의 **[신규] 버튼과 동일한 경로**를 탄다. *(§8, HPMS `design.md §6.1`)*
- [x] Given 어느 화면이든, When 도움말 단축키를 누르면, Then **현재 화면에서 사용 가능한 단축키 목록**이 표시된다.
- [x] Given 라이트/다크 테마, When 팔레트와 단축키 도움말을 열면, Then 두 테마 모두에서 shadcn/ui + lucide 규약대로 렌더된다. *(§8)*
- [x] Given 네트워크가 없는 환경, When 팔레트로 검색·이동·생성을 하면, Then 전부 정상 동작한다. *(N4)*
- [x] Given 팔레트를 여닫고 명령을 실행, When 활동 타임라인·이벤트를 확인하면, Then 팔레트 사용 자체는 이벤트를 만들지 않고, 실행된 도메인 명령만 N7 범위대로 기록된다. *(§9 N7 — 조회·검색은 감사 제외)*

> 결정됨(S5-D5): `Cmd/Ctrl+K`(팔레트) · `?`(도움말) · `Esc`(닫기) · `↑↓`(이동) · `Enter`(실행).
> 단일 문자 바인딩은 텍스트 입력에 포커스가 없을 때만 듣는다.
> 결정됨(S5-D5): 키맵 커스터마이즈는 범위 밖이다. 저장할 곳이 `.local/`(기기 고유·백업 비대상,
> D5)뿐이라 기기를 옮기면 사라진다.
> 결정됨(S5-D5): 팔레트는 **쓰기를 하지 않는다.** 허용하면 전이표·claim 결합·`If-Match`를
> 팔레트 경로에서도 지켜야 하고 그것은 두 번째 쓰기 경로다 — 이 프로젝트가 세 번 확인한 대로
> 같은 규칙의 사본은 어긋난다. 이동·검색·내보내기만 한다.
> 결정됨: `role="dialog"` + `aria-modal` + `role="listbox"`/`option` + `aria-selected`를 쓰고,
> 활성 항목은 배경색과 **왼쪽 세로선** 둘로 표시한다 — 색만으로는 구분되지 않는 독자가 있다(§8).
> 결정됨(S5-D5): 격리 이슈는 **결과에 보이되 표시한다.** 깨진 이슈를 찾아가려는 사람이 쓰는
> 도구가 팔레트인데 숨기면 고칠 방법이 사라진다.
> 결정됨: 최근 방문·최근 명령 이력은 범위 밖이다(저장 위치가 키맵과 같은 문제를 갖는다).
>
> ⚠ **AC10은 닫히지 않는다 — 웹 UI에 이슈 생성 경로가 없다.** 그 인수조건은 "툴바 우측의
> [신규] 버튼과 동일한 경로"를 전제하는데 그 버튼도, 생성 폼도, `POST /issues`를 부르는 클라이언트
> 코드도 존재한 적이 없다. r01a가 생성을 API·CLI로만 만들었고 화면 쪽은 어느 스토리 범위에도
> 없었다. 구현 실패가 아니라 **제품에 빈 곳**이며, 팔레트 스토리가 그것을 드러냈다.
> S5-D5대로 팔레트가 쓰기를 하지 않으므로, 채우더라도 생성 폼을 여는 명령이 되어야 한다.
