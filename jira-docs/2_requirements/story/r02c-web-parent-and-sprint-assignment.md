# 웹 부모·스프린트 지정 — 후보를 서버가 고르고 사람이 정한다

> R2와 R6의 **화면 절반**이자, 웹에 남은 마지막 빈 곳이다. `r02a`가 계층과 `validateParent`를,
> `r06`이 스프린트 계획과 용량을 만들었지만 **화면에서 이슈에 부모나 스프린트를 붙일 수 없다.**
> `r01d`(수정 폼)는 두 필드를 의도적으로 범위 밖에 두었다 — "uid를 사람이 붙여넣는 형태 이상은
> 별 스토리"라고.
>
> 그 "uid를 붙여넣는 형태"가 이 스토리가 피해야 할 것이다. 부모는 `uid`로 지정하는데(§5.1),
> ULID를 사람이 눈으로 고르는 일은 없다. 그러니 **고를 수 있는 것을 화면이 보여줘야** 하고,
> 무엇이 고를 수 있는 것인지는 **서버만 안다** — 타입 규칙(`epic`만 부모가 될 수 있다), 순환
> 금지, 격리 상태, 그리고 스프린트 쪽의 "닫힌 스프린트는 받지 않는다"까지.
>
> `r01e`에서 삭제 전략 목록을 서버의 409에서 받아 온 것과 같은 이유다. 규칙의 사본을 화면에
> 두면 규칙이 바뀌는 날 어긋난다.

## 사용자 스토리 (User Story)

> **As a** 에이전트가 적재한 백로그를 정리하는 개발자·PO,
> **I want** 이슈 상세에서 부모 에픽과 스프린트를 **목록에서 골라** 붙이기를,
> **so that** uid를 어딘가에서 복사해 오거나 터미널로 옮겨 가지 않고, 고를 수 없는 것을
> 골랐다가 거부당하는 왕복도 하지 않는다.

## 인수 조건 (Acceptance Criteria)

### 부모 지정

- [x] Given 이슈 상세, When 부모 칸을 보면, Then 현재 부모가 **키와 제목으로** 표시된다 — uid가 아니라. 없으면 "최상위"로 보인다. *(§5.1, §8)*
- [x] Given 부모를 바꾸려 함, When 후보 목록을 열면, Then **서버가 고른 후보만** 나온다. 화면은 타입 규칙의 사본을 갖지 않는다. *(§5.1, r01c와 같은 원칙)*
- [x] Given `story`·`task`·`bug`·`spike`, When 후보를 보면, Then `epic`만 나온다. `subtask`면 `story`·`task`·`bug`·`spike`가 나온다. *(§5.1 계층 규칙)*
- [x] Given `epic`, When 부모 칸을 보면, Then **부모를 지정할 수 없다는 사실이 표시되고** 목록이 열리지 않는다 — `epic`은 항상 최상위다.
- [x] Given 자기 자신과 자기 하위, When 후보를 보면, Then **나오지 않는다.** 고르면 반드시 `E_PARENT_CYCLE`이 될 것을 후보로 내밀지 않는다.
- [x] Given 격리된 이슈, When 후보를 보면, Then 나오지 않는다. *(§5.6)*
- [x] Given 후보를 고름, When 저장하면, Then `PATCH /issues/{key}`가 `parent`만 담아 **한 번** 호출되고 상세·목록이 갱신된다.
- [x] Given 부모가 있는 이슈, When [최상위로]를 누르면, Then `parent: null`로 저장되어 부모가 없어진다.
- [x] Given 서버가 거부하는 조합, When 응답을 받으면, Then **서버가 준 메시지**를 그 자리에 보여주고 선택이 지워지지 않는다.

### 스프린트 지정

- [x] Given 이슈 상세, When 스프린트 칸을 보면, Then 현재 스프린트가 **이름과 상태로** 표시되고, 없으면 "백로그"로 보인다. *(§8)*
- [x] Given 스프린트를 고르려 함, When 목록을 열면, Then **담을 수 있는 스프린트만** 나온다 — 닫힌 스프린트는 새 이슈를 받지 않는다(`E_SPRINT_CLOSED`). 어느 것이 담을 수 있는지는 서버가 정한다.
- [x] Given 스프린트를 고름, When 저장하면, Then `PATCH /issues/{key}`가 `sprint`만 담아 호출되고, 보드·번다운이 그 이슈를 포함해 갱신된다.
- [x] Given 스프린트가 지정된 이슈, When [백로그로]를 누르면, Then `sprint: null`로 저장되어 스프린트에서 빠진다.
- [x] Given 열린 스프린트가 하나도 없는 프로젝트, When 목록을 열면, Then 빈 상태 안내가 보이고 오류가 아니다.

### 쓰기 경로와 표기

- [x] Given 두 지정 모두, When 헤더를 확인하면, Then 상세를 읽을 때 받은 **그 ETag가 `If-Match`로** 실린다. 어긋나면 412이며 덮어쓰지 않는다. *(D15)*
- [x] Given 아무것도 고르지 않고 닫음, When 처리하면, Then 요청을 보내지 않는다 — 변경 없는 쓰기는 파일도 미커밋 배지도 건드리지 않아야 한다. *(AC24)*
- [x] Given `issue:edit` 권한이 없는 역할·토큰, When 상세를 보면, Then 두 칸 모두 읽기 전용이다. *(§6.4, AC7)*
- [x] Given 저장 후, When 활동 타임라인을 보면, Then `issue.updated`가 바뀐 필드의 before/after와 함께 남는다. *(§9 N7)*
- [x] Given 라이트/다크 테마, When 두 칸을 열면, Then 기존 규약으로 렌더되고 의존성 0개 바닐라를 유지한다. *(S2-D1)*
- [x] Given `Esc`, When 목록이 열려 있으면, Then 닫히고 포커스가 열기 직전 요소로 돌아간다. Tab이 밖으로 새지 않는다. *(r01e에서 만든 공용 트랩)*
- [x] Given 네트워크가 없는 환경, When 두 지정을 하면, Then 정상 동작한다. *(N4)*

> ⚠ 미정: 후보가 많을 때(에픽 수십 개) 검색·필터를 붙일지. 지금 보드 규모에서는 목록으로
> 충분하고, 필요해지면 R4의 검색을 재사용한다.
> ⚠ 미정: 백로그 화면에서 **여러 이슈를 한 번에** 스프린트에 담는 경로. `POST /sprints/{id}/issues`가
> 이미 있고 `r06`의 계획 화면이 그 자리일 수 있는데, 이 스토리는 상세 한 건만 다룬다.

> **만들다 나온 것(2026-08-03).** **다크 테마가 글자색을 한 번도 뒤집지 않고 있었다.**
> `--ink`·`--muted`는 라이트에서 한 번 선언되고 끝이며, 아래 다크 규칙들은 전부 *배경*만
> 덮어썼다. 그래서 `#detail-title`이 `#1a1f1c` 패널 위에 `#17201b`로 찍혔다 — 어두운 판에
> 검은 글자다. 제 요소만의 문제가 아니라 **모든 제목·카드 제목·값이 그랬다.**
>
> 여러 스토리가 "라이트/다크 두 테마 모두에서 렌더된다"를 인수조건으로 걸고 체크했지만
> **아무도 색을 재 보지 않았다.** `r01e`의 포커스 트랩과 같은 종류의 거짓 초록이다.
> 다크 블록의 손으로 쓴 규칙들이 이미 쓰던 값(`#dfe6e1`·`#9fb0a5`·`#2c342e`)으로 변수를
> 정의해 맞췄고, 대비를 실측했다 — 본문 13.2:1, 라벨 7.3:1 (WCAG AA는 4.5:1).
>
> **후보를 서버에서 받는 판단은 값을 했다.** 처음엔 "타입 규칙 정도는 화면에 둬도 되지
> 않나" 싶었는데, `subtask`의 부모가 `story`·`task`·`bug`·`spike` 넷이라는 것과 `epic`은
> 부모를 가질 수 없다는 것, 그리고 닫힌 스프린트가 거부된다는 것까지 세 규칙이 걸렸다.
> 화면에 뒀으면 셋 다 사본이 됐다.
>
> **테스트 픽스처를 한 번 잘못 만들었다.** 하위 배제를 검증하려고 에픽 아래 스토리를 만들고
> 그 스토리 밑으로 에픽을 옮겼는데, 그건 **진짜 사이클**이라 Stage B가 둘 다 격리해 버렸다.
> 스토리를 최상위로 두고 에픽만 그 아래로 옮겨야 사이클 없이 "후보가 자기 하위인" 상태가 된다.
