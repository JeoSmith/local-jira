적재 계정 정리 중 발견. records.ts의 userRecords.apply가 파일에 있는 사용자를 INSERT OR REPLACE로 upsert만 하고, 파일에서 사라진 행을 지우지 않는다.

users.yaml은 집합 전체를 담은 단일 파일이라 적용은 병합이 아니라 교체여야 한다. 이슈·스프린트는 엔티티당 파일이라 삭제가 파일 삭제로 처리되지만 이 파일만 예외다.

재현: alice(admin)·bob(member) 생성 → users.yaml에서 bob 줄 삭제 → index reconcile → user list에 bob이 그대로 남는다. index rebuild를 해야 사라진다. 추가는 정상 반영되고 역할 변경도 REPLACE로 반영되므로, 오직 '제거'만 조용히 무시된다.

role이 권한을 결정하므로 이건 보안 문제다. 문서화된 SoT 방식대로 파일을 고쳐 사람을 내보내도 실제로는 아무 일이 일어나지 않고, 동료의 제거 커밋을 pull 해도 마찬가지다. 전체 재빌드 전까지 그 계정은 계속 유효하다.
